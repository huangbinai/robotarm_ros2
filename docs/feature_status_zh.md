# reBotArm 功能状态与验收矩阵

## 状态定义

- **稳定实现**：代码、边界检查和离线测试已具备，仍需对应平台验收。
- **实验性**：功能链路存在，但参数、设备兼容或长期稳定性仍需验证。
- **兼容层**：只为旧入口保留，不接受新功能。
- **待平台验收**：Windows 无法完成，必须在 VMware/Ubuntu 或实机执行。

## 当前自动化基线

当前全量离线回归、目标 Python 包的 `compileall` 和 `git diff --check` 均应通过。POSIX 虚拟串口、真实 ROS 2 运行时和显式性能基准会在不满足运行条件的平台上跳过。这些结果证明代码层回归未发现失败，不代表机械臂已完成真机安全认证。

## 已明确不迁入

- P0 Gate B/C 真机验收工具；
- 依赖 Windows 直接访问 MotorBridge 的运行方案；
- 无有效 GraspNet 候选时自动生成简化抓取动作的旧回退；
- 在 `rebotarm_interactive_control` 中继续堆叠新业务实现。

## 建议验收顺序

1. Ubuntu 构建和依赖导入；
2. 无硬件仿真和 MoveIt；
3. 仅连接、不使能、反馈新鲜度；
4. 显式使能、当前位置保持和可靠失能；
5. 单轴小幅动作与夹爪边界；
6. 多点轨迹、取消、抢占和异常恢复；
7. 重力补偿、示教回放；
8. 视觉 plan-only；
9. 低速实机抓取和重复性统计；
10. 语音 real 模式与独立主从跟随工具。
