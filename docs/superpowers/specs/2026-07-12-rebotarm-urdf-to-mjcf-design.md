# reBotArm URDF 到 MJCF 生成设计

## 目标

以项目现有 `rebotarm.urdf` 为机器人模型的唯一权威来源，使用 MuJoCo 官方 URDF 解析能力生成并在本地保存完整 MJCF。转换脚本与生成后的 `robot.xml` 一同纳入版本控制；正常运行直接加载 MJCF，只有 URDF 或 STL 更新时才手动重新生成。

本阶段不连接实机，不启动硬件后端，不开展强化学习训练。原始 STL 同时用于显示和碰撞，不再进行 VHACD 凸分解或毫米级近似误差验收。

## 模型生成架构

生成链路如下：

```text
rebotarm.urdf + 原始 STL
          ↓
MuJoCo 官方 URDF 解析器
          ↓
基础 MJCF
          ↓
确定性后处理
          ↓
robot.xml（自动生成并提交）
          ↓
scene.xml（手写场景层）
```

`rebotarm.urdf` 负责定义机器人 link、joint、坐标变换、轴、限位、质量、惯量以及 STL 引用。转换脚本不得修改原始 URDF 或 STL。

确定性后处理仅补充 URDF 无法完整表达的 MuJoCo 专用内容：

- 六轴和夹爪执行器；
- 双指夹爪联动关系；
- 接触参数与必要的碰撞过滤；
- 默认姿态和仿真所需的 MuJoCo 元数据。

生成的 `robot.xml` 顶部必须标明它是自动生成文件，不应手工编辑。`scene.xml` 继续作为手写场景层，负责地面、灯光、相机和测试物体，不由生成器覆盖。

## 本地存储与同步

MJCF 和 STL 均保存在本地项目目录中。MuJoCo 运行时只读取本地文件，不依赖网络或 GitHub。

Git 用于版本管理和双端同步：Windows 生成并提交 URDF、STL、转换脚本和 MJCF；Ubuntu VM 同步仓库后，在自己的本地目录中构建和运行。两端必须使用相同文件，生成结果及受控资产的 SHA-256 应一致。

## 生成与一致性检查

转换工具提供两种模式：

- 生成模式：从权威 URDF 重新生成 `robot.xml`；
- `--check` 模式：在临时位置执行相同转换并与已提交文件比较，不修改工作区。

相同输入、固定 MuJoCo 版本和固定转换配置必须产生一致的规范化 MJCF。URDF、STL、生成配置或转换结果发生变化，而仓库中的 `robot.xml` 未更新时，`--check` 必须失败并给出明确差异原因。

## 运行接口

GUI 与无界面模式加载同一个本地 `scene.xml`。现有 Python API 继续提供：

- 读取关节位置和速度；
- 设置六轴关节目标；
- 控制夹爪；
- 步进仿真；
- 重置状态。

ROS 2 节点继续沿用现有 joint 名称和消息接口，接收关节轨迹并发布仿真关节状态。底层模型改为自动生成的 MJCF，不改变上层 Python 和 ROS 2 调用方式。

## 安全边界

- 所有生成、测试和验收均不连接实机；
- 默认使用仿真后端和 `use_hardware:=false`；
- 转换工具不得探测串口、CAN、网络机械臂或其他硬件；
- ROS 2 验收只启动 MuJoCo 仿真节点及必要的软件接口；
- 任何需要硬件的 launch 或控制入口都不属于本设计范围。

## 删除范围

删除已经放弃的 VHACD 路线相关内容：

- VHACD 生成脚本、配置和依赖文件；
- 修复后的夹爪碰撞 STL；
- 所有凸分解 STL 与 manifest；
- VHACD 专项测试；
- VHACD 设计和实施文档；
- 未通过验收的未提交实验产物。

保留原始 URDF、原始 STL、MuJoCo Python/GUI/headless/ROS 2 接口、场景文件、通用安全检查和双端同步说明。

## 验证与完成标准

自动测试和人工冒烟验收应覆盖：

1. 一条命令可由 URDF 生成本地 `robot.xml`；
2. 相同输入重复生成结果一致，`--check` 通过；
3. MJCF 能被当前固定版本 MuJoCo 正常加载；
4. 六个机械臂关节和两个夹爪关节的名称、方向、限位正确；
5. link 的质量、惯量和 STL 引用与 URDF 一致；
6. 原始 STL 正常显示并作为碰撞 mesh 使用；
7. 夹爪可以开合，并能与场景测试方块产生基础接触；
8. GUI 和无界面模式均能启动；
9. Python API 回归测试通过；
10. ROS 2 无硬件模式能够构建、启动并收发预期接口；
11. Windows 与 Ubuntu VM 中的受控文件哈希一致；
12. 验收过程中没有连接或驱动真实机械臂。

本设计以“忠实转换现有 URDF 并保持现有软件接口可用”为完成条件，不再以 VHACD 几何误差作为 MuJoCo 基础环境的完成门槛。
